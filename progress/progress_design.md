# 写作进度追踪表 · 设计文档

> 本文档是「写作进度追踪表」（`progress.py`）的设计依据，记录 2026-09-21 至 09-22 讨论中确定的全部规则。
> 实现前若有改动，先更新本文档；后续新增功能也在此追加。

---

## 一、目标与定位

**要解决的问题**

手上有若干本 LaTeX 笔记（多章多节、章节拆成独立 .tex 文件的结构），需要知道：每本写到哪了、哪一节还没动、自己在哪些地方留了欠账。这些问题靠翻目录看不出来。

**核心价值**

1. **揭示真实进度**——把「为加快编译而主动注释掉的章」与「从未动工的章」区分开。前者计入，后者排除，否则进度会被后者严重拉低。
2. **记住欠账**——默认认为已写完；只在你自己发现某处还没弄利索时标记，形成一份待补清单。

**交付形态**

本地 Python 服务（`127.0.0.1`）+ 浏览器页面。不部署公网，不做手机端。

---

## 二、技术架构

| 组件 | 作用 |
|---|---|
| `progress.py` | 服务本体。仅用 Python 标准库（`http.server` / `json` / `subprocess` / `pathlib`），零第三方依赖 |
| `progress_ui.html` | 前端页面。CSS/JS 全部内联、零外链，由服务在 `/` 路由下返回 |
| `progress.conf` | 配置：笔记根目录、端口、TeXStudio 路径、排除规则（首次运行自动生成） |
| `progress_marks.json` | 标记数据：三维标记、备注、待办、章统计覆盖、计划标记（运行时自动生成） |
| `progress.md` | 脚本使用说明（运行方式 / 实际输出 / 界面说明 / 行为细节） |

> 实现说明：前端拆为独立文件而非内嵌进 `progress.py`，便于单独编辑与语法高亮，降低单文件过大导致的出错风险。所有运行时数据文件（`progress.conf` / `progress_marks.json`）均由脚本自动生成。

**启动方式**

- 主入口：若工作区已有总入口面板，可在其中增加一项调用本脚本。调起后**立即返回**，服务在后台运行。
- 次入口：命令行 `python progress.py`。
- **不做 `.bat`**：`.py` 的文件关联因机器而异，双击不一定能跑起来，入口统一走命令行。

**端口**

默认 `8765`，被占用则顺延（8766、8767…），可在 `progress.conf` 修改。启动后自动打开浏览器一次。

**重复启动**

检测到服务已在运行，则只打开浏览器，不再启动第二个进程。

**关闭**

页面提供「退出服务」按钮。服务停止时页面须显示明确提示（如"服务已停止"），不可静默失败。

**打开文件机制**

页面向本地服务发请求，服务用 `subprocess.Popen` 调起 `texstudio.exe "<路径>"`。

- 当 `.tex` 已在系统里关联 TeXStudio 时，注册表链为 `HKEY_CLASSES_ROOT\.tex` → ProgID → `"<TeXStudio 路径>" "%1"`，据此自动探测编辑器位置
- **不走 `file://` 链接**：Chrome 会把 `.tex` 当纯文本直接在页面里显示，不会交给外部程序。
- 移动端/窄屏隐藏该按钮（本设计不开放手机访问，此条为防御性规则）。

## 三、数据来源与扫描

### 3.1 解析方式

- 从每本笔记的 `main.tex` 出发，**递归展开 `\input` 树**，**不硬编码目录层级**。
  - 原因：各笔记目录深度不统一。有的为 `main → 章 index → 节 index → 小节`（3 层），有的为 `main → 节 index → 小节`（2 层，无章级 index）。
- 解析 `\input{...}` 必须做**花括号配对**，不得用 `[^}]*`。
  - 原因：路径可能含 LaTeX 花括号，如 `Content/7_The_additive_groups_R^{n}/index`。
- 解析出目标后，**不以 `Path.suffix` 判断是否要补 `.tex`**，改为「路径不以 `.tex` 结尾就补」。
  - 原因：文件名本身可能含点，如 `1_The_complexes_Ku,_K.u,_C,_Ku,_C`，后缀会算成 `.u,_C,_Ku,_C` 这种伪后缀，于是漏补 `.tex`，真实存在的文件被误判成「未建」。
- 用 `seen` 集合去重，防止同一目标被多个 `\input` 重复累加。
- 注释行（`%` 开头）中的 `\input` 记为「未纳入编译」，其条目信息保留，用于四象限判定。
  - **这一条对 `main.tex` 与各级 `index.tex` 一视同仁**。早期实现只在 `main.tex` 落地，各级 `index.tex` 中注释掉的 `\input` 被整棵跳过 —— 后果是它下面挂的节 / 小节在界面上**整块消失**（如某本笔记第 1 章注释掉的第 3、4 节，共 8 个文件从未出现在树里）。
- 既没被引用、也没以注释形式出现的 `.tex` 不进树（工作台反映的是笔记结构，不是目录内容），但收集起来在明细页底部单独列出。

### 3.2 判定「有内容」

剔除以下内容后，剩余字符数 **> 50** 即视为已写：

- 空行
- `%` 注释行
- `\part` / `\chapter` / `\section` / `\subsection` / `\subsubsection` 标题行
- `\input` 行

### 3.3 统计指标

- 定理环境数
- 环境内字符数 / 环境外字符数（陈述性文字）
- 行数
- 空环境数（环境内容 < 20 字符）
- `\begin` / `\end` 配对情况

### 3.4 定理环境清单

`structure.sty` 定义，共 17 个：

```
definition  axiom   hypothesis  theorem   lemma    proposition  corollary
metatheorem criteria problem    example   remark   exercise     algorithm
convention  alarm   sketch
```

- `proof` 与 `sketch` 特殊：用于追踪「证明」维度。
- 排版与数学环境（`enumerate`、`align*`、`itemize`、`tikzcd`、`cases` 等）视为内容的组成部分，**不计入环境数**。

### 3.5 排除规则

写入 `progress.conf` 可调：

- 隐藏目录、下划线开头的目录（如 `__pycache__`、`_backup_*`）
- 编译产物 23 种后缀（aux / log / out / toc / pdf 等）
- conf 中 `ignore` 列出的目录名

### 3.6 性能

扫描以目录遍历 + 逐文件读取为主，其中逐文件读取占大头；整体**亚秒级**完成。

结论：**每次打开页面或点刷新即全量重扫**，不做缓存与增量机制。

### 3.7 标题提取

标题**按笔记的层级模式**取（见 7.5）：一个 tex 文件里出现的每个标题命令都记下来
（`\part` / `\chapter` / `\section` / `\subsection` / `\subsubsection` 与附录命令），
再由「这一层对应哪个命令」决定用哪个 —— 不能笼统地取「文件里第一个标题」，
因为本笔记体系里**每一层的标题只写一次**，节目录的 `\section` 写在它第一个叶子中，
而那个叶子自己的标题是 `\subsection`。

| 节点 | 标题来源 |
|---|---|
| 顶层（章 / 部分） | `main.tex` 里 `\input` 上方的 `\chapter{...}` / `\part{...}` |
| 目录 | 自身 `index.tex`，或子树第一个文件里属于该层的标题 |
| 叶子 | 自己文件里属于该层的标题 |
| 附录 | `\appendixchapter`（节位）/ `\appendixsubsection`（小节位） |

- 缺失时以英文目录名 / 文件名兜底（去掉编号前缀、下划线转空格）。
- 显示时须清理 `\texorpdfstring{$\R^{n}$}{Rn}` 这类包装（含数学符号的节标题里很常见）。
- 标题行**不计入正文字数**（否则只有一行标题的占位文件会被判成「有内容」）。

## 四、进度口径

### 4.1 小节三态

| 状态 | 判定 | 进度条颜色 |
|---|---|---|
| 已写 | 实质内容 > 50 字符 | 蓝 `#378ADD` |
| 已建空壳 | 文件存在但实质内容为 0 | 中灰 `#888780` |
| 规划未建 | 索引中有 `\input`，文件不存在 | 深灰 `#5F5E5A` |

实践中文件要么是刚建的空壳、要么已写成篇，中间态很少，故阈值取 50 足够稳健。

### 4.2 章的四象限

| 未纳入编译 | 有已写内容 | 处理 |
|---|---|---|
| 否 | 有 | 计入 |
| 否 | 无 | 计入（占分母，待写） |
| **是** | **有** | **计入**，标注「未编译」（中性灰字，非警示色） |
| **是** | **无** | **排除**，不占分母 |

同一套规则也适用于中间层被注释的节。

同一套四象限**按层级递归**：早期只在顶层章上应用，各级 `index.tex` 中被注释的节 / 小节一律视为「计入」，与设计不符；现已统一。

### 4.3 手动覆盖（优先级：手动 > 自动）

每章一个统计状态：

| 状态 | 含义 |
|---|---|
| 自动（默认） | 按 4.2 规则判定 |
| 强制计入 | 无论自动判定如何，均计入统计 |
| 强制排除 | 无论自动判定如何，均排除 |

界面对手动设置过的章显示「手动」标记，与自动判定区分。

设置理由：自动统计会出错，且有时是系统性错误。实例——某本习题集的章节索引只引用了 2 个文件，于是算出「100%」，而实际有 247 个文件。此类问题自动规则永远修不好，必须留手动出口。反向的「强制计入」同样必要，以防自动误判为无内容。

### 4.4 百分比

- **结构进度** = 已写小节数 ÷ 计入章的规划小节数
- **确认完成率** = 已确认完成的小节数 ÷ 总小节数（受三维标记影响）

## 五、三维标记

### 5.1 三个维度（挂在小节级）

| 维度 | 含义 |
|---|---|
| 环境 | 该节的定理环境是否写完 |
| 正文 | 该节的陈述性文字（环境外的段落）是否写完 |
| 证明 | 该节的证明是否写完（`proof` / `sketch`） |

**默认值：全部为「已完成」。** 有内容的小节默认即完成，只在你自己发现没弄利索时手动改为「待补」。

### 5.2 形态

**不是复选框**（空框的默认态语义为"未完成"，与需求相反），而是可点击的**状态标记**：

- 已完成：低调的灰色对勾
- 待补：醒目的橙色空心圈 `#EF9F27`
- 点击即切换，再点切回

位置：列表行内并排三个；详情面板内以「标签 + 状态文字 + 标记」呈现。

### 5.3 批量开关

「证明」维度提供批量操作：把某章所有无 `proof` / `sketch` 的小节一次标为证明待补。

现状参考：实际写作中 `\begin{proof}` 与 `\begin{sketch}` 都很少见，多数小节的证明直接写成正文。

### 5.4 备注与待办（两者并存，分开两块）

| 类型 | 用途 | 形态 |
|---|---|---|
| 备注 | 说明性文字，如"这里暂时跳过，等写到第 5 节再回来补" | 多行自由文本 |
| 待办 | 动作条目，如"补第 3 个命题的证明" | 可勾选的列表，逐条添加 |

分开的理由：二者语义不同，混在一起会产生"一条没勾的备注算不算待办"这种说不清的状态。

- 备注**不参与进度计算**，纯备忘。
- 有小节的备注 / 待办时，列表行内显示一个小标记，详情面板内编辑。

### 5.5 章级标记

- 章行右侧显示**小节级标记的自动汇总**（如「3 节待补」，只读）。
- 章级另有一个**独立的手动标记**（如「整章待补」），用于不好归到某一节的问题。
- 两者并存，语义不同。章级标记**不是**"一键把整章所有小节标为待补"的批量开关（那会让汇总失真）。

### 5.6 计划标记

「设为下一步」——给某节打上标记，在续写区顶部突出显示。比备注更主动。

## 六、提示规则

### 6.1 两条硬提示（确定的问题）

1. `\begin` 与 `\end` 不配对（编译必然报错）
2. 环境内容为空（< 20 字符）

### 6.2 三条软提示（值得看一眼）

3. 环境数 < 同节其他小节中位数的 1/3
4. 同节其他小节都有 `proof` / `sketch`，本节没有
5. 同节其他小节都有陈述文字，本节为零

### 6.3 核心原则

**软提示只能用相对判断（同一「节」内各小节横向比较），绝不能用绝对阈值。**

原因：正文以外文字占比本身很低，若按绝对阈值判断，几乎每一节都会亮灯，噪声淹没信号。若整个节都没有正文，那是用户的写法风格，不是异常。

### 6.4 呈现方式（三层）

| 层 | 形式 |
|---|---|
| 行内 | 小圆点：红＝硬问题，琥珀＝软提示；悬停显示原因 |
| 详情面板 | 「值得留意」区块，写明判断依据（如"环境 3 个，本节其他小节平均 9 个"） |
| 筛选 | 顶部筛选项增加「待补 / 可疑」 |

### 6.5 中性的信息展示

详情面板直接显示「环境 N 个 / 陈述文字 M 字符」，为 0 时用灰字标出——这是中性信息，不是警告。

## 七、界面设计

### 7.1 导航

**五项**：总览、明细、欠账、统计、设置。PC 用左侧边栏切换，窄屏用底部 Tab。
「总览」只做速览，内容多了就跳到专门的页（欠账 / 统计）—— 不把速览撑成一个长页。

**续写区不设独立导航项**，而是占据总览页顶部。

### 7.2 顶部状态条（固定）

最后扫描时间 + 刷新按钮 + 服务状态 + 亮暗切换 + 导出报告。

### 7.3 总览页

自上而下：

1. **续写区**（置顶）
   - 最近改动的 N 个文件（按内容哈希判断真实改动，纯改名不算）
   - **清除**：把当前这一批当作已看过（本地水位，存 `localStorage`），之后再有新改动
     才重新出现；不是「永久关掉这个区块」。
   - 停滞提醒：某本笔记超过 N 天无改动则标出
   - 「设为下一步」的节
   - ⚠️ 上面第一条的「按内容哈希」**尚未实现** —— 现在只按 `mtime`，所以「打开过」
     或「只顺手改了一下标题格式」的文件也会进列表。这正是「清除」按钮存在的直接原因；
     要根治得给每个文件存一份上次已知的内容指纹（见 12 节偏差表）。
2. **全库合计卡片**
   - 总小节数、已写数、待补数、定理环境总数
3. **9 张笔记卡片**
   - 字段：笔记名、三段式进度条 + 百分比、已写/规划小节数、定理环境数、总字数、未编译章数、待补标记数、停滞提醒
   - **不含「最后改动时间」字段**（该信息仅用于排序与停滞判断）
   - 未启用章数用灰字体现
   - 点击卡片 → 跳明细页并定位到最近改动的那一章
4. **排序**：默认按最近改动降序，可切换按名称

### 7.4 明细页

- **左：三层树**（章 → 节 → 小节），手风琴式
  - 默认只渲染章级；**默认展开最近改动的那一章**
  - **未启用的章默认也进树**（灰显 + 章名后标「未启用」），其下小节照常可展开、可点开、可标记，只是不计入统计 —— 否则这些小节在页面上彻底看不到，会被当成「工作台没显示全」。工具栏「未启用章」按钮可收起它们
  - 章行：显示名 + 三段式迷你条 + 已写/总数 + 小节级待补汇总 + 章级标记
  - 小节行：状态点 + 显示名 + 行尾三个标记
  - 未建条目**按序号插入原位**，不排到末尾（这样能看出"写到第 8 节断了"的连续断口）
  - 排序按数字前缀自然序（须处理 `010_` 这类带前导零的历史目录，不能按字符串排）
- **右：详情面板**（PC 固定栏，窄屏底部抽屉）
  - 选中小节：标题、路径、三个标记、统计数字、备注、待办、操作按钮
  - 选中章 / 节：统计数字、整章待补、批量标记、计入范围（原来只有小节详情，
    「批量标记」这类章级操作没有落点）
- **顶部**：笔记切换 + 筛选（全部 / 已写 / 未写 / 未建 / 待补 / 可疑）+ 搜索框 + 两个开关（「编辑范围」、「未启用章」）
  - **笔记选择器自适应**：≤ 12 本平铺成一排按钮（一眼看全、一次点击）；更多则收成一个下拉 ＋
    「‹ ›」前后切换，避免工具栏被标题撑爆。阈值只影响呈现，两条路径的功能完全一致
    （切换都走同一个 `selectNote()`）。按钮组本身也允许换行，所以即便在阈值内遇上长标题
    也不会横向溢出。
- **底部**：两个默认折叠的分组
  - 「未启用章节（N）」：显示顶层节点名、小节数、状态说明、排除原因（用词随层级模式变「章」/「部分」）
  - 「未纳入索引的文件（N）」：既没写进 `index.tex` 也没以注释形式出现的游离 `.tex`。不进树（不属于笔记结构），但必须列出，否则会被误认为「没显示全」

### 7.5 层级模式：节点显示名与编号规则（2026-09-24 重写）

**层级模式（levels）** 决定树的每一层对应哪个 LaTeX 标题命令，例如
`chapter, section, subsection`（章-节-小节）。它是**按笔记分别设置**的，来源有两处：

1. **「设置」页里逐本指定** —— 写进 `progress_settings.json`（键是笔记目录名），
   优先级最高，界面上标「指定」；下拉里的模式与「新建大纲」的 `LEVEL_PRESETS`
   是同一套（运行时直接读 `new_note.py`，不抄第二份）。
2. **自动识别** —— 最外层命令取自 `main.tex`（`\part` / `\chapter` / `\section`），
   其余按 LaTeX 章节命令的固定次序顺延到**树的层数**。不去逐层「投票」读到了什么
   命令，那会被「某层没有自己的标题」这类写法带偏（与 `outline_tool` 导出大纲同一口径）。
   所以 `main.tex` 用 `\chapter`、树 3 层的笔记 → `chapter, section, subsection`。

> `\part` 名只对应一个 `\input` 时，顶层才算「部分」；先 `\part` 再并列多个 `\input`
> 的写法里，那些 `\input` 各自是章 —— 与编号口径一致。

**显示名的来源**（本笔记体系里每一层的标题只写一次，落点有约定）：

| 节点 | 显示名 |
|---|---|
| 顶层（部分 / 章） | `main.tex` 里该 `\input` 上方最近的 `\part{...}` / `\chapter{...}` |
| 目录节点 | 自身 `index.tex` 里属于该层的标题；没有就往子树**第一个**文件里找 |
| 叶子 | 自己文件里属于该层的标题（`\section` / `\subsection` …） |
| 附录 | `\appendixchapter`（写在**节位**）/ `\appendixsubsection`（写在**小节位**） |
| 兜底 | 去掉编号前缀、下划线转空格的目录名 / 文件名（`1_Terms_and_relations` → `Terms and relations`） |

> **一个文件里可能有两个标题**：节目录的标题 `\section` 写在它第一个叶子中，而该叶子
> 自己的标题是 `\subsection`。所以取标题时必须按「这一层对应哪个命令」来取，
> 不能笼统地取「第一个标题」—— 否则目录会显示成英文目录名、第一个叶子会顶着它父目录的标题。
>
> **层级模式与实际命令对不上时**（例如把 `chapter,section,subsection` 结构的笔记显示成
> `part,chapter,section`）退回一条兜底规则：叶子取自己文件里**最深**的标题（那是它自己的），
> 目录取子树里**最浅**的标题（那是它这一层的）；顶层始终优先用 `main.tex` 里的标题。

> **childless `index.tex` 按叶子处理**：`index.tex` 既没有 `\input`、同目录也没有别的
> `.tex` 时，它就是那一层的内容单元，走叶子分支（因此能像小节一样展开三维标记与备注）。
> 目录形态只看「有没有子项」，不看它自己写了哪个标题命令。
>
> 反向的教训也记一笔：早期版本靠「`index.tex` 里有没有 `\chapter`」判断它是不是容器，
> 那等于把层级写死在代码里；改成按层级模式取标题后，这个判据就不再需要。

**编号按笔记的完整结构**（与层级模式一一对应）：

- **顶层是「部分」**：部分号用中文数字并写入显示名（`第一部分：集合论`），其下的章
  仍用全书统一的章号（`\part` 不占章号）。
- **顶层是「章」**：章号写进显示名（`第1章：集合论`），其下依次 `1.1`、`1.1.2`。
- **附录** 走附录自己的计数器、用字母编号：`附录 A：…`、其下 `A.1`（有 `\part` 时为
  `第1部分.1`）—— 与 `structure.sty` 的 `\theapx` / `\theapxsec` 同一算法。
- **被 `main.tex` 注释掉的 `\input` 同样参与编号**。这一点与「按 LaTeX 计数器编号」不同，
  是刻意的：编号要反映**笔记的章节结构**，而不是编译产物。若按计数器走，被注释掉的首章
  会拿不到编号，后面各章整体前移，与作者对笔记结构的认知相悖。是否纳入编译另由「未编译」
  标注体现。
- **只有实际存在的文件占序号** —— 未建的文件在 PDF 里不存在，不占号。

**设置页（层级模式的入口）**

- **显示**：一个开关 —— 明细页是否默认显示未启用的顶层节点。默认**开**：未启用的章
  在树里灰显列出，其下小节照常可展开可标记。与明细页工具栏上那个按钮是同一项设置。
- **笔记层级模式**：每本笔记一行，下拉选择。列表 = `自动识别` ＋ `new_note.py` 的
  `LEVEL_PRESETS`（运行时直接读它，保证与「新建大纲」同一套）＋ 以 `\part` 开头的
  序列（那边没有简写名，但「部分-章-节」的显示需求是真实存在的）。同时显示「自动 /
  指定」标记与识别依据，手动项可逐个或一键恢复自动。
- **数据文件**：说明设置在 `progress_settings.json`（见 8.4）。

改层级模式要**重扫**（标题与编号都在扫描期算出来），因此这一项 POST 之后会走全量扫描
（数秒）；只改显示开关则复用缓存。

### 7.6 未启用章节分组

- 位置：明细页底部，默认折叠
- 内容：顶层节点名、小节数、状态说明、排除原因（用词随层级模式变成「章」或「部分」）
- 手动排除的与自动排除的用不同标记区分
- 这些章已在上方树里灰显列出，此分组只作集中说明与一键「计入」的入口

**「未纳入索引的文件」分组**（2026-09-22 补充）

- 同样位于明细页底部、默认折叠
- 收录：笔记目录下存在、但既没被任何 `\input` 引用、也没以 `%` 注释形式出现的 `.tex`
- 不进树 —— 工作台反映的是笔记的章节结构（由 main.tex 与各级 index.tex 定义），不是目录里有什么就显示什么
- 列出文件名、状态（有内容 / 空）、字数、最后修改，可一键用 TeXStudio 打开
- 来历：写到一半还没挂进索引的小节，或改名后忘删的旧文件

### 7.9 搜索（2026-09-24）

- **多关键字 AND**：查询按空白切分，**全部命中**才算匹配；大小写不敏感。
  例：`张量积 模` → 标题里同时含这两个词的小节（`两个模的张量积` 等）。
  不做 OR —— 多词 OR 的结果太散，等于没筛。
- **匹配范围**：显示名（中译名）与文件名（`pretty_name` 之后：已去编号前缀、下划线转空格）。
  正文的范围见 7.10：搜索框右侧的「仅标题 / 标题+正文」开关，默认连正文一起查
  （走服务端检索），关掉后退回纯标题过滤、不发请求。
- **高亮**：命中词在树行标题里用 `<mark>` 标出；先 HTML 转义再插标签，长词优先
  （否则短词会先吃掉长词的一部分，高亮被切碎）。
- **自动展开**：搜索期间，子树里含命中项的目录**临时展开**（不改用户的展开状态）；
  **清空搜索后把这些目录并入展开状态**，上下文不至于突然收起 —— 用「上一次的查询词」
  重算一遍即得，不依赖渲染时的中间状态（否则中途搜过一次无结果的词就会把记录冲掉）。
- **命中计数**：搜索框右侧显示「命中 N 节」/「无匹配」（只数当前会在树里出现的小节）。
- 与状态筛选**叠加**（取交集）：先按状态筛，再按关键字匹配。

### 7.10 正文检索与源码 / PDF 预览层（2026-09-24 追加）

**为什么要做**：标题检索只能回答「哪一节讲这个」，回答不了「哪一节里提到过这个」——
而后者才是写作时最常见的提问（某个记号、某个术语在哪用过）。

- **范围开关**：搜索框右侧「仅标题 / 标题+正文」。默认含正文；关掉就退回纯前端过滤，
  不发任何请求。
- **索引方式**：扫描时本来就要读每个 tex 文件，顺手把原文按相对路径留在内存里
  （`STATE["texts"]`），检索因此是内存操作。不引入倒排索引 —— 全库 tex 只有几 MB，
  线性扫一遍比维护索引简单得多，也不会因为文件改动而失效。
- **词间 AND**：同一文件里都出现过即命中（可以在不同行）；命中的小节在树里照常
  高亮标题、自动展开，行尾另标「正文 N」（命中处数）。
- **结果面板**：搜索有结果时右侧面板切换为按笔记分组的命中清单（行号 + 命中处
  附近片段，片段里高亮关键词）。点树上的节点就切回详情 —— 结果与详情用
  `panelMode` 区分，不各占一块。
- **预览层（全屏）**：这是「装得下」的答案 —— 命中上下文、源码、PDF 都不塞进侧栏，
  而是开一个覆盖全屏的层：左边源码片段（行号、命中行底纹、关键词高亮），右边 PDF。
  顶部可切「并排 / 只看源码 / 只看 PDF」，窄屏自动改为上下叠。
- **PDF 定位**：`pdftotext`（TeXLive 自带）抽出每页文本 → 两边去空白后比对 →
  得到命中页；**跳转页取最长连续段的第一页**（目录页通常孤立，正文讨论则连续数页）。
  iframe 用 `/api/pdf?note=<笔记>#page=N` 打开，交给浏览器内置阅读器。
  页文本按「路径 + mtime」缓存；PDF 重新编译后自动失效。
- **诚实边界**：PDF 是编译产物，可能与源码不同步 —— 预览层底部标出 PDF 编译时间，
  并提示「以源码为准、要精确定位到词请用 Ctrl+F」。找不到 pdftotext 或缺 main.pdf
  时，预览层仍给源码，只说明原因。

### 7.11 欠账页（2026-09-24 追加）

**为什么要做**：总览页的续写区是**速览** —— 固定几条（设为下一步 ≤ 2 条、最近改动 N 个、
停滞提醒），回答不了「一共有哪些欠账、最久没动的在哪」。欠账需要一个能筛选、能排序、
能就地处理的落点；总览页只留聚合与入口。

**术语边界（重要）**：「欠账」是伞形概念，涵盖下面四类来源，但**不等同于其中任何一类**。
「待补」在本工具里**特指**三维标记中的某一项为 todo —— 它是四类之一，不是全部。

| 来源标签 | 含义 | 数据落点 |
|---|---|---|
| 待补 | 三维标记（环境 / 正文 / 证明）中至少一项为待补 | `entries[].marks` |
| 待办 | 该小节待办清单里尚未勾选的条目 | `entries[].todos` |
| 下一步 | 被「设为下一步」的小节 | `entries[].planned` |
| 整章待补 | 章 / 节上的手动标记 | `nodes[].chapter_mark` |

- **只统计计入范围内的条目** —— 与 `chapter_mark`、`pending` 的既有口径一致：
  `node.excluded` 为真的一律不进清单。
- **一个来源一行**：小节的三维待补**合并成一行**（行内列出哪几维待补，逐维可切）；
  待办按**条目**分行（一条一行）；「下一步」「整章待补」各一行。
- **工具栏**：来源多选（默认全选）、笔记筛选（全部 / 各本）、排序（默认「最久未动在前」，
  另可切「章节顺序」）、右侧「共 N 条」。
- **清单行**：`笔记 › 章 › 节`面包屑 + 来源标签 + 内容 + 最后修改 + 停滞天数。
  点标题/面包屑 → 跳明细页、展开沿途目录并选中该节点。
- **行内动作** —— 本页是欠账的**唯一写入口**，写入复用现有的 `POST /api/entry` 与
  `POST /api/chapter`，**不新增接口、不新增第二套写路径**：

  | 行类型 | 动作 |
  |---|---|
  | 待补 | 三个维度的小标记，点一下把该维度切回「已完成」 |
  | 待办 | 勾选框 |
  | 下一步 | 取消下一步 |
  | 整章待补 | **只有**「取消整章待补」一个动作 |

- **整章待补的落点**：它挂在章 / 节节点上，没有对应的小节行。照常列一行，面包屑到章 / 节为止。
- **停滞天数**：`(扫描时刻 − 该节点 last_mtime)` 折算成天。阈值复用 `progress.conf` 的
  `stagnant_days`（默认 14，由 `/api/data` 下发），**不另造第二套阈值**。
- **总览页入口**：续写区顶部一行「欠账清单 · 共 N 条 →」，跳到本页。
  **徽标数与「共 N 条」必须由同一个函数算出**（前端 `collectPending()`，两处调用它），
  否则会出现同屏两个数字不等、看起来像算错。
- **不搬进本页**：「最近改动」与「停滞提醒」是**活动流水**，不是欠账余额，留在总览页。
- **零后端改动**：四类来源的字段（`marks` / `todo_count` / `todos` / `planned` /
  `chapter_mark` / `last_mtime`）本来就都在 `/api/data` 里。

### 7.12 统计页（2026-09-24 追加）

- **范围**：一个选择器切换「全库 / 各本笔记」。x 轴的单位随之变化 —— 全库时是**笔记**，
  单本时是该笔记的**章（顶层节点）**。图 1 ~ 图 3 共用这个范围。
- **不引图表库**：本工具对外的承诺是「不联网、不上传」，前端 CSS/JS 全部内联、零外链。
  所以图表一律手写 SVG；长条类图直接复用现有 `.bar`（HTML/CSS），不必为了「像图表」
  去写一套 SVG 坐标轴。

| # | 图型 | 口径 | 数据来源 |
|---|---|---|---|
| 1 | 各章 / 各笔记 × 状态堆叠条 | 每单位一条：已写 / 空壳 / 未建，按 `planned` 归一；右侧标绝对数 | `stats.written/empty/missing` |
| 2 | 沿单位的结构折线 | 三条序列可切：①平均每节环境数 ②正文占比 ③平均每节字数 | `stats.envs/body_chars/chars/written` |
| 3 | 各章 / 各笔记 × 欠账来源堆叠条 | 每单位一条：待补 / 待办 / 整章待补；「下一步」另色单列 | `collectPending()` 按单位分组 |
| 4 | 定理环境构成环形图 | 17 类占比，只标 top 5，长尾并入「其他」 | `stats.env_names` |

- **图 4 的图例紧贴环形**（2026-09-24 修正）：名称与数字相邻（名称给固定最小宽度、
  数字不再 `margin-left:auto`）。早先 `.envLeg` 是 `flex:1` + 数字右对齐，在宽卡片里
  数字被推到最右侧，与环之间空出近千像素。
- **图 4 另带一张「构成明细表」**（2026-09-24 追加）：粒度跟随范围（全库 → 笔记 / 章，
  单本 → 章 / 节），行首三角展开下一层；列 = 该范围内出现过的环境类型（按合计降序取
  前 6 类，其余并入「其他」）+ 「合计」；零值单元格写「·」而不是 0，免得一片 0 糊住版面。
  - **每行取该节点整棵子树的汇总**，与明细页点开该节点看到的「定理环境 N 个」**同源** ——
    所以逐级相加都能对上。实测在全部 2161 个节点上 `Σ env_names == stats.envs` 均成立。
  - 展开出的下一层**不按计入范围过滤**：否则子行加不回父行。被排除的下一层标「未启用」、
    数字照实显示（明细页也照常显示它的数字）—— 这样「结构汇总」与「进度统计」两套口径的
    差异是**看得见的**，而不是两个页面各说各话。
  - 合计行 == 环形中心数；单本范围下也 == 该笔记的 `counted.envs`（与笔记卡片一致），
    全库范围下 == `global.envs`（与合计卡一致）。

- **图 2 的分母用「已写小节数」（`stats.written`），不用规划数** —— 否则未建的章会把
  密度拉低，反映不出内容性质。分母为 0 的单位**不画点**（那是「没有数据」，不是「密度为零」）。
- **图 2 的横向布局按「每个单位固定宽度」排，不再按容器宽度均分**（2026-09-24 修正）：
  - 每个单位占 `STEP = 64px`，图宽 = `max(560, 左轴 + (n-1) × STEP + 右余量)`，
    SVG 用**固有像素尺寸**（不再 `width:100%` 缩放），容器 `overflow-x:auto` ——
    放不下就横向滚动，放得下就不滚。
  - 早先按容器宽度均分 + `width:100%` 缩放有两个后果：① 最右标签被画布裁掉；
    ② 标签数超过 12 个时**隔一个跳一个**（`step = ceil(n/12)`），于是「某些章的标题
    根本没显示」。现在标签一律全显示。
  - 标签用**短形式**：章取「第N章」（用正则从显示名里截出前缀），笔记模式退回短标题。
    **完整标题放在图下方的清单里**（`第1章：集合论`，无数据的单位在该处标「无数据」）——
    轴上只放得下短标签，全名放轴下。
  - 因为不再缩放，轴标签实际字号回到了 CSS 里的 10px（此前被 1.3 倍放大到约 13px）。
- **折线在缺口处断开**：没有数据的单位不画点，也**不跨过它连线** —— 连线会暗示一段
  并不存在的趋势。全库模式下常常只有 3 本笔记有内容，于是图上就是 3 个孤立点 + 5 个
  「无数据」，而不是一条只画到一半的线（这正是早先看起来「画了一半就没了」的原因：
  x 按全部单位均分，但只画有数据的点）。
- **悬停看数值**：命中区是**整张图**（不是那 3px 的小圆点）——按鼠标横坐标就近取单位，
  显示提示框（单位全名 + 当前序列名与数值，无数据则写明）+ 一条竖向指示线。
  用 `<title>` 挂在圆点上的做法已放弃：命中区太小，实际只有极少数点能碰到。
- **图 2 三条序列一次只显示一条**，用切换按钮，不堆多轴 —— 同一张图上叠三条量纲不同的
  曲线，读的人要先猜哪条是哪条。
- **图 3 只统计计入范围内的单位**，与 7.11 同一口径、共用 `collectPending()` ——
  一处算、两处用。
- **数据来源（图 1 / 图 2 / 图 4）**：全库范围取 `note.counted`（与服务端的进度统计、
  笔记卡片同一口径）；单本范围取顶层节点的 `stats`（与明细页的树、详情面板同一口径）。
  两者在「整章被排除」这一点上一致；只有在**手动强制排除一个仍有内容的章**时才会有差异 ——
  那时章级 `stats` 含该章、`counted` 不含。自动排除永远不产生差异：四象限规则排除的是
  「未纳入编译且无内容」的整枝，环境数与字数本就是 0。
- **图 4 按 `decision` 只统计计入范围内的章**，与图 1 的全库口径对齐 —— 否则未启用章的
  环境会被算进环形图，和另两张图对不上。
- **图 1 的回答**是「每章还剩多少、剩的是没建还是空壳」；**图 2 的回答**是「这章是定义堆
  还是论述堆」—— 后者与完成度无关，所以折线不与图 1 重复。
- **不做**：
  - 状态构成环形图 —— 与合计卡的三段式进度条完全重复，是装饰；
  - 正文 / 环境内字符散点图 —— 要再补一个聚合字段，且可读性差、每次看都要先解释怎么读。

**`env_names` 的汇总**：`file_metrics` 本来就算了每个文件的 `env_names`，但 `aggregate()`
一直没往上累加，所以整本 / 全库的环境构成取不到。现在给 `node["stats"]` 加上 `env_names`
（叶子取自身、目录由子项累加、内容写在 `index.tex` 里的章按 `self_metrics` 并入），
供图 4 使用。

- **只新增字段，不改任何判定分支**：`STAT_KEYS` 不动，所以 `counted` / `overall` /
  合计卡 / 笔记卡片 / 导出报告里的数字一个都不变。改完做 A/B（停用新逻辑后跑同一份扫描，
  计入判定与统计应零差异）。

## 八、数据结构

### 8.1 `progress_marks.json`

```json
{
  "version": 1,
  "updated": "2026-09-22T10:26:47+08:00",
  "nodes": {
    "<笔记>/Content/8_Fields_Theory": {"mode": "force_exclude", "manual": true}
  },
  "entries": {
    "<笔记>/Content/3_.../2_preorder_relations.tex": {
      "marks": {"env": "done", "body": "done", "proof": "todo"},
      "note": "这里暂时跳过，等写到第 5 节再回来补",
      "todos": [
        {"text": "补第 3 个命题的证明", "done": false},
        {"text": "核对定义 2 的措辞", "done": true}
      ],
      "planned": true,
      "fingerprint": "<内容指纹，用于路径迁移>"
    }
  }
}
```

- `nodes` 每条记录两个字段，都可缺省：`mode`（计入范围）、`chapter_mark`（整章待补）。
  两者独立 —— 同一章可以既被强制排除、又挂着整章待补。
- `mode` 取值：`auto` / `force_include` / `force_exclude`
- `marks` 取值：`done` / `todo`
- `fingerprint`：由文件内容生成，用于目录改名后的标记迁移

### 8.2 写入健壮性

- **原子写入**：先写临时文件再替换，防止写一半中断导致 JSON 损坏
- 每次写入自动留一份 `.bak`
- 启动时校验 JSON，损坏则从 `.bak` 恢复并提示

### 8.3 备份

- 页面提供「导出 / 导入 JSON」按钮
- 导入时按**时间戳合并**（新数据覆盖旧数据），不丢失任一侧记录

### 8.4 `progress_settings.json`

设置独立成文件，与标记数据分开存 —— 标记是「工作产物」，设置是「查看偏好」，
混在一起会让两边都容易被误删。

```json
{
  "version": 1,
  "updated": "2026-09-24T15:02:11",
  "show_unused": true,
  "note_levels": {"Note_B": "part,chapter,section"}
}
```

- `show_unused`：明细页是否默认显示未启用的顶层节点（默认 `true`）。
- `note_levels`：键是**笔记目录名**，值是层级模式的命令序列；没写的笔记按结构自动识别。
  写成 `auto` 等于删除该项（POST 时会 `pop` 掉）。
- 同样是原子写入 + `.bak`；文件不存在 = 全默认；删掉它即恢复默认。
- 界面改设置走 `POST /api/settings`，`/api/data` 每次都把当前设置原样下发，
  以免页面拿到上一次扫描时的旧值。

## 九、笔记目录变动的处理

| 情形 | 处理 |
|---|---|
| 新增笔记 | 扫描时自动识别（含 `main.tex` 且有 `Content/`），无需手动注册 |
| 目录改名 | **迁移功能**：按**内容指纹**匹配，把旧路径的标记迁到新路径上。用户按项目惯例频繁加编号前缀，此功能必要 |
| 笔记删除 | 标记保留（可能只是临时移走），看板上不再出现该笔记 |
| 无法匹配的标记 | 保留记录并标为「已失效」，**不自动删除** |
