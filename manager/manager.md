# manager.py

笔记工作区管理面板：用于在**新环境**中准备 Git、配置远程账户，并统一管理笔记根目录下各子文件夹的仓库。

## 运行

```bash
python manager.py          # 进入交互式面板
python manager.py --help   # 显示用法
```

配置保存在脚本同目录的 `manager.conf`（含本机路径，已列入 `.gitignore`）。

## 面板选项

运行后命令行窗口显示：

```
==============================================================
  笔记工作区管理面板
==============================================================
  笔记根目录：D:\笔记目录
  已识别仓库：10 个 / 子文件夹 12 个
  远程账户　：moranzhuying
--------------------------------------------------------------
  1. 检测环境（git 安装 / 用户配置 / SSH 密钥 / 远程连通性）
  2. 配置 Git 账户（用户名、邮箱）
  3. 配置 SSH（生成密钥 / 写 config / 测试连通 / 显示公钥）
  4. 设置笔记根目录（扫描子文件夹，识别仓库）
  5. 显示各仓库状态（远程 / 分支 / 改动数 / 领先落后）
  6. 批量提交并推送（对所有有改动的仓库）
  7. 为未入版本控制的文件夹创建仓库并首次推送
  8. 退出
--------------------------------------------------------------
  9. 符号库管理（进入 symbols.py 的面板）
 10. 笔记工具（选一本笔记 → 提交 / 切换习题模式）
--------------------------------------------------------------
  可多选，用英文逗号分隔（如 1,3,5）
```

| 选项 | 功能 |
|---|---|
| 1 | 检查 git 是否安装、用户名与邮箱是否配置、`~/.ssh` 下有无公钥、`~/.ssh/config` 是否指向 443 端口，并实测与 GitHub 的连通性 |
| 2 | 交互式设置 `user.name` 与 `user.email`（写入全局 git 配置，回车保持不变） |
| 3 | 生成 ed25519 密钥（若不存在）、向 `~/.ssh/config` 写入 github.com → `ssh.github.com:443` 的配置、显示公钥内容供复制到 GitHub、可选测试连通 |
| 4 | 设置笔记根目录并扫描子文件夹，统计其中的 git 仓库数；同时可设置远程账户名 |
| 5 | 列出各仓库的分支、改动文件数、相对远程的**领先/落后提交数**、远程仓库名；并列出尚未入版本控制的子文件夹 |
| 6 | 先让用户勾选要操作的仓库（默认只列有改动的），再统一执行 `add → commit → push`；可选择「只推送、不提交」 |
| 7 | 为尚未入版本控制的文件夹创建仓库：补 `.gitignore` 与 `.gitattributes`、`git init`、首次提交；`gh` 可用时自动在 GitHub 建仓库并推送，否则打印手动命令 |
| 8 | 退出 |
| **9** | **进入 `symbols.py` 的符号库管理面板**，退出后返回本面板 |
| **10** | **笔记工具**：选一本笔记后，可调用该目录下的 `commit.py`（提交并推送）或 `setup_mode.py`（切换习题编排模式） |

选项 9、10 是**子工具入口**——它们不重复实现功能，而是调用已有的脚本，因此各脚本的职责保持不变（见文末「与 commit.py 的分工」）。

## 配置项（manager.conf）

| 键 | 含义 |
|---|---|
| `root` | 笔记根目录 |
| `account` | GitHub 账户名（选项 7 创建远程仓库时使用） |
| `ignore` | 扫描时忽略的子文件夹名（逗号分隔） |

例：

```
root = D:/笔记目录
account = moranzhuying
ignore = BasicAlgebraExercises
```

> 名称中含 `Archieved` 的文件夹（归档）与以下划线开头的文件夹会被自动忽略。

## 实现说明

- **清屏**：每次进入选项前清屏，画面只保留当前选项的内容；`os.system` 不可用时以空行代替。
- **连通性测试**用 `ssh -T git@github.com`，注意 GitHub 在此命令上**返回码非 0 也属正常**（它以返回码表示"认证成功但不提供 shell"），因此判定依据是输出中是否含 `successfully authenticated`，而非返回码。
- **选项 7 的两种路径**：优先用 `gh repo create <名字> --public --source=. --push` 一步完成；`gh` 不可用时退化为「本地初始化 + 打印手动命令」，不依赖任何外部认证。
- **选项 6 的推送失败不算整体失败**——本地提交已成功，脚本会明确指出这一点并建议重跑。

## 推送失败的自动处理

选项 6 的推送失败时，按下列顺序自动处理：

1. **重试两次**（间隔 3 秒、6 秒）；
2. **尝试备选通道**——远程是 SSH 地址时，改用 **22 端口**再试一次（本机默认走 `ssh.github.com:443`，两端口互补；若 22 端口成功，脚本会提示可把 `~/.ssh/config` 的 `Port` 改为 22）；
3. **归类报错**——区分认证失败、域名解析、连接超时、未配置远程、仓库不存在、需先 pull 等情形，给出对应的检查方向。

全部失败时，汇总里会标注该仓库「本地提交已成功」。

## 与各脚本的分工

工作区里共有四个脚本，作用域与职责各不相同：

| 脚本 | 位置 | 作用域 | 职责 |
|---|---|---|---|
| **`manager.py`** | 工作区根 | 全部笔记 | 环境检测与配置、批量提交、建仓库；并作为**总入口**调用下列脚本 |
| `symbols.py` | 工作区根 | 全部笔记 | 符号库的提取 / 回填 / 刷新补全 / 分发 |
| `commit.py` | 各笔记目录内 | **当前一本笔记** | 提交并推送（支持 `--log` 联动 CHANGELOG） |
| `setup_mode.py` | 各笔记目录内 | **当前一本笔记** | 切换习题编排模式 |

**为什么不全合并**：`commit.py` 与 `setup_mode.py` **必须在具体的笔记目录内运行**——前者依赖同目录的 `.git`，后者读写同目录的 `Content/` 与 `ExerciseBook/`。这使它们可以「就地运行」：

```bash
cd D:/笔记目录/Algebra      # 正在写这本
python commit.py "补充第 3 章"    # 直接提交，无需切换目录
```

若把它们并入 `manager.py`，每次提交都要先切到工作区、再从菜单里选笔记，反而多两步。因此保留了两个层次：

- **写笔记时**：在笔记目录里直接运行 `commit.py`（最顺）；
- **换机器、加新笔记、批量同步时**：运行 `manager.py`，从面板统一操作。

`manager.py` 的选项 9、10 提供了从面板进入这些脚本的通道，从而只需记住一个入口。
