# manager.py

笔记工作区管理面板，统一管理**工作区**内各仓库 —— 查看状态、批量提交推送、为尚未入版本控制的文件夹创建仓库。

**作用域是整个工作区，不只是笔记区**：状态总览与批量提交会覆盖「笔记区」（`manager.conf` 的 `root`）、「模板区」与「工具区」，按区域分组显示。

## 运行

```bash
python manager.py          # 进入交互式面板
python manager.py --help   # 显示用法
```

配置保存在脚本同目录的 `manager.conf`。

## 面板选项

运行后命令行窗口显示：

```
==============================================================
  笔记工作区管理面板
==============================================================
  笔记根目录：<你的笔记根目录>
  已识别仓库：N 个 / 子文件夹 M 个
  远程账户　：<你的 GitHub 账户>
--------------------------------------------------------------
  1. 设置笔记根目录（扫描子文件夹，识别仓库）
  2. 显示各仓库状态（远程 / 分支 / 改动数 / 领先落后）
  3. 批量提交并推送（对所有有改动的仓库）
  4. 为未入版本控制的文件夹创建仓库并首次推送
  0. 退出
--------------------------------------------------------------
  可多选，用英文逗号分隔（如 1,3）
```

| 选项 | 功能 |
|---|---|
| 1 | 设置笔记根目录并扫描子文件夹，统计其中的 git 仓库数；同时可设置远程账户名 |
| 2 | **跨区域**列出各仓库的分支、改动文件数、相对远程的**领先/落后提交数**、远程仓库名；并列出尚未入版本控制的子文件夹 |
| 3 | 先让用户勾选要操作的仓库（**跨区域**，默认只列有改动的），再统一执行 `add → commit → push`；可选择「只推送、不提交」 |
| 4 | 为尚未入版本控制的文件夹创建仓库：补 `.gitignore` 与 `.gitattributes`、`git init`、首次提交；`gh` 可用时自动在 GitHub 建仓库并推送，否则打印手动命令 |
| 0 | 退出 |

## 配置项（manager.conf）

| 键 | 含义 |
|---|---|
| `root` | 笔记根目录 |
| `account` | GitHub 账户名（选项 4 创建远程仓库时使用） |
| `ignore` | 扫描时忽略的子文件夹名（逗号分隔） |

例：

```
root = D:/笔记目录
account = <你的 GitHub 账户>
ignore = Some_Ignored_Dir
```

> 名称中含 `Archieved` 的文件夹（归档）与以下划线开头的文件夹会被自动忽略。

## 实现说明

- **清屏**：每次进入选项前清屏，画面只保留当前选项的内容；`os.system` 不可用时以空行代替。
- **连通性测试**用 `ssh -T git@github.com`，注意 GitHub 在此命令上**返回码非 0 也属正常**（它以返回码表示"认证成功但不提供 shell"），因此判定依据是输出中是否含 `successfully authenticated`，而非返回码。
- **选项 4 的两种路径**：优先用 `gh repo create <名字> --public --source=. --push` 一步完成；`gh` 不可用时退化为「本地初始化 + 打印手动命令」，不依赖任何外部认证。
- **选项 3 的推送失败不算整体失败**——本地提交已成功，脚本会明确指出这一点并建议重跑。

## 推送失败的自动处理

选项 3 的推送失败时，按下列顺序自动处理：

1. **重试两次**（间隔 3 秒、6 秒）；
2. **尝试备选通道**——远程是 SSH 地址时，改用 **22 端口**再试一次（两个端口互补；若 22 端口成功，脚本会提示可把 `~/.ssh/config` 的 `Port` 改为 22）；
3. **归类报错**——区分认证失败、域名解析、连接超时、未配置远程、仓库不存在、需先 pull 等情形，给出对应的检查方向。

全部失败时，汇总里会标注该仓库「本地提交已成功」。
