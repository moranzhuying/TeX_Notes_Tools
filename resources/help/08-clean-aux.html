8. 清理编译产物

删掉 aux / log / synctex 这类可再生的中间文件。只在「有 .tex 源」的目录里动手。

面板入口创建与维护 → 卡片「清理编译产物」→ 选区域 → 执行
命令行python tools/clean_aux/clean_aux.py

默认扫 LaTeX_Notes，列出目录 / 文件数 / 大小 / 类型；不勾「真正删除」就只是清单。（点击图片用看图器放大）

什么时候用

  • 编译产物攒了几百兆，想清一清。
  • 仓库体检提示「误跟踪了编译产物」，想知道到底有哪些。
  • 换机器前想瘦身，但不想误删笔记正文。

怎么做

  1. 选扫描区域（整个工作区 / LaTeX_Notes / Template / Tools）。
  2. 先不勾「真正删除」，执行，看清单。
  3. 确认清单里没有想留的东西，再勾「真正删除」执行一次。

界面上每项的意思

项说明
扫描区域默认 LaTeX_Notes；Tools 区域指工具集自身。
连 PDF 一起删只删「与同目录某个 .tex 同名」的 PDF，不会碰下载的电子书。
真正删除不勾只列清单。这是唯一的安全阀。

命令行用法

python tools/clean_aux/clean_aux.py --dry-run
python tools/clean_aux/clean_aux.py --area LaTeX_Notes --write

文件都在哪

内容位置
删除范围只动扩展名在清单里的中间产物；outputs/、SkillProjects/、_logs/、_state/ 默认跳过
不动的东西.tex 源、图片、PDF 电子书、转写日志
这个工具会真删文件，且不进回收站。第一次用某个区域时，务必先跑一遍不勾「真正删除」的清单。

常见问题

Q：清单里有我不认识的文件

A：看「类型」列：aux / log / synctex 都可再生。fdb_latexmk 是latexmk 的依赖记录，删了只是下次全量编译。

Q：能恢复吗？

A：不能，不进回收站。所以清单必须先看。真要保险，先提交一次 git。

Q：为什么 outputs/ 里的 log 没被清？

A：那里混着转写日志与运行日志，不是 LaTeX 产物。工具只在「同目录有 .tex」的地方动手。

Q：删完编译变慢了

A：正常。latexmk 的增量信息（fdb_latexmk / fls）被清掉了，下一次是全量编译。
